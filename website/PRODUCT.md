# Product

## Register

brand

## Users

Engineers and AI/LLM developers building browser agents. They are usually
evaluating whether a browser runtime is technically credible, then moving into
the docs to install it, understand the page format, and integrate it into an
agent loop.

## Product Purpose

TideSurf connects browser agents to live Chromium through CDP. It compresses
the rendered DOM into compact text, assigns snapshot-scoped action handles, and routes
the model's chosen action back to the real page. The website should make that
loop understandable in under a minute and make the implementation feel safe to
adopt.

## Brand Personality

Humane, exact, quietly opinionated. TideSurf should feel like a thoughtful
developer made a small, serious tool and explained it plainly.

## Anti-references

- Generic SaaS landing pages with glossy cards, gradients, or inflated claims.
- Terminal cosplay, neon developer-tool styling, and decorative code wallpaper.
- Docs templates whose branding stops at a recolored sidebar.
- Hover interactions that scale, rotate, translate, or replace the words under
  a reader's pointer.
- Dense corporate copy that repeats the same product claim in every section.

## Design Principles

1. Practice the product: remove visual wrapper noise and keep useful meaning.
2. Use the MercuriusDream reference for rhythm, not as a bag of decorations.
3. Show the real DOM-to-text artifact instead of describing it repeatedly.
4. Let flat color patches punctuate content; never turn them into chrome.
5. Make landing and docs feel like one place while letting each serve its job.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Keep visible keyboard focus, 44px mobile hit areas,
reduced-motion support, readable contrast, inert closed navigation, and no
primary content that depends on animation or client-side observation to become
visible.

The live page, distilled for agents.

A browser agent does not need another screenshot. It needs the page distilled into readable text, with handles that still point back to real things in Chromium. TideSurf sits in that gap.

$ bun add @tidesurf/core

Keep the page real. Make the context smaller.

TideSurf reads the rendered page, keeps the parts an agent can use, and gives every actionable thing a short handle. The model chooses a handle; DevTools carries it back to Chromium. Less selector ceremony, more actual browsing.

tokens from a real GitHub issues page, before and after TideSurf compresses the DOM. Headings, links, buttons, inputs, tables, and visible copy stay — with stable handles like L1 B2 I3 that stay connected to the elements the model wants to use.

Browser automation reads better when the browser is still alive.

TideSurf does not ask the model to invent selectors or parse a visual guess. It hands over a compact text surface, then routes the chosen handle through DevTools — so the page the agent reads is the page that is actually there.

Compress the page, not the meaning.

Wrapper markup, generated classes, scripts, and presentational noise recede. Anything a person can read and use remains visible to the agent.

02

Let handles become actions.

The same ID the model reads can click, type, select, scroll, extract, and move across tabs. Less selector ceremony, more actual browsing.

Keep control close to home.

Launch Chrome from TideSurf or attach to a running session. Cookies, auth state, and local debugging stay where developers expect them.
